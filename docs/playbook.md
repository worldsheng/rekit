# 接单手册

技术只解决一半问题。这份手册解决另一半：**客户从哪来、怎么报价、怎么交付、怎么不被坑**。

---

## 一、先把话说清楚：市场是分层的

逆向需求分三个市场，价格结构完全不同：

| 市场 | 典型需求 | 价格特征 | 客户特征 |
|---|---|---|---|
| **公开平台** | 单 App 逆向、改个功能、破个注册 | 被压到 1–2k，大量骗单/灰单 | 一次性，比价，不问过程 |
| **私域** | 协议还原、算法提取、长期维护 | 3k–3w，可复购 | 有明确业务，认人 |
| **企业** | 竞品分析、恶意样本分析、安全评估 | 合同制，月结 | 要发票、要报告、要合规 |

**真相**：公开平台上标价几十万的单，绝大多数是骗单或者灰产钓鱼。真实成交价不会出现在标价栏里。

所以策略是：**公开平台只用来练手和攒评价，真正的钱在私域和企业。**

## 二、客户从哪来（按见效速度排）

### 1. 作品集 + 内容（慢，但决定上限）

- 每做完一个案例，脱敏写成分析文章
- 发在：个人博客 + 知乎 + 公众号 + GitHub（工具）
- 关键词布局：写具体问题，不写"逆向入门"这种大词
  - 好：`某笔记 App 本地数据库加密格式还原`
  - 差：`逆向学习笔记（一）`

**见效周期**：3–6 个月开始有人私信。之后是复利。

### 2. 圈子（中等速度）

- Telegram 逆向/破解相关群：**潜水看需求**，别一进去就发广告
- 看别人怎么报价、怎么交付、客户抱怨什么
- 有人发需求时，私聊给一个**具体的技术判断**，不是"我能做"

### 3. 平台（快，但质量差）

- Upwork / Freelancer：搜 `reverse engineering`，看**有评价的成交项目**而不是挂牌价
- 国内平台（猪八戒/互站）：单子杂，灰单多。**接之前先判断需求本身合不合法**

### 4. 老客户复购（最值钱）

一个客户做过一次，后面所有类似需求都找你。维护成本几乎为零。

> 收入结构健康的标志：**60% 以上来自复购或转介绍**。全是新客户说明你在平台里打转。

## 三、需求澄清：接单前必须问的 8 个问题

少问一个，后面就多吵一次。

```
1. 目标是什么？        "破解"太模糊。是要明文、要能改、要能自动化、还是要一份报告？
2. 输入输出是什么？    给什么文件/账号/接口，期望拿到什么格式的结果
3. 环境是什么？        系统版本、软件版本、是否加固、是否有反调试
4. 期限？              什么时候要，超时怎么算
5. 验收标准？          怎么算"做完了"——这一条必须落到可检验的动作
6. 用途？              自用、公司内部、商业产品集成
7. 是否需要持续维护？  软件更新后要不要跟着更新，怎么收费
8. 预算范围？          让对方先说区间，不要自己先报
```

**第 6 条（用途）不是道德审查，是风险控制。** 客户拿你的工具去诈骗，聊天记录是你唯一的证据。

## 四、报价

### 三种报法

| 方法 | 适用 | 做法 |
|---|---|---|
| **按工时** | 需求不明确、探索性 | 估小时数 × 时薪，写明"超出部分另计" |
| **按难度档** | 同类需求做过 | 低/中/高三档固定价，快 |
| **按价值** | 客户能算出收益 | 客户省了多少成本/赚了多少，取一部分 |

### 现实参考（**样本小，仅供锚定，不是行情表**）

| 需求 | 常见区间 | 说明 |
|---|---|---|
| 单 App 接口逆向（签名还原） | 1–3k | 公开平台压到 1–2k |
| 协议还原 + 重放工具 | 3–10k | 要交可运行脚本 |
| 脱商业壳（ASPack/PECompact 级） | 2–5k | 虚拟化壳另算 |
| 算法提取 + 复现脚本 | 3–15k | 看算法复杂度 |
| 恶意样本分析报告 | 2–8k/份 | 含 IOC 和处置建议 |
| 长期维护（按月） | 2–10k/月 | 软件更新跟进 |

**这些数字不是承诺。** 唯一可靠的定价方式是：先做一个小样（收 20–30% 定金），做完再谈全款。小样能证明能力，也能筛掉白嫖的。

### 报价话术

```
先说范围，再说价：
"这个需求我理解为 X。做法是 Y，大概需要 Z 天。
 交付物是：可运行脚本 + 说明文档 + 一次远程调试。
 报价 N，先付 30% 定金，验收后付尾款。
 如果中途需求变化超过 30%，重新报价。"
```

不要报"看情况"。报一个区间 + 一句"具体做完评估后确认"。

## 五、交付

### 交付物清单（按这个给，显得专业）

```
1. 结果文件          —— 解密后的数据/可运行的脚本
2. README            —— 怎么跑、依赖什么、参数怎么填
3. 简要说明          —— 关键逻辑 3–5 段，不写教程
4. 复现步骤          —— 客户能自己验证
5. 已知限制          —— 哪些情况不支持
6. 变更记录          —— 如果迭代过
```

第 5 条最重要。**主动写限制的交付，客户信任度翻倍。**

### 验收

- 让客户按你写的步骤自己跑一遍
- 跑通再收尾款
- 跑不通，先改，不要辩解

## 六、风控

### 三条硬线

1. **问清用途，留记录。** 微信/Telegram 聊天记录保存。客户说"破解别人的账号"，直接拒。
2. **不转包，不代收。** 中间人抽成看着轻松，出事时你是第一责任人。
3. **不碰支付/身份/通讯录类数据。** 这类需求即使客户说"自用"，性质也接近诈骗或侵犯公民个人信息。

### 常见坑

| 坑 | 表现 | 防法 |
|---|---|---|
| 白嫖 | "先做出来看看效果" | 收定金再动手 |
| 需求漂移 | 做着做着加功能 | 需求变更超 30% 重新报价 |
| 验收赖账 | "感觉不太对" | 验收标准写成可检验动作 |
| 二次分发 | 客户把你的工具卖给别人 | 合同写明授权范围 |
| 拿去违法 | 事后才知道 | 用途问清楚 + 留记录 |
| 平台骗单 | 标价高、要求先交保证金 | 任何要你先付钱的都是骗 |

## 七、第一个月做什么

```text
第 1 周
  □ 装环境（roadmap 阶段 0）
  □ 用 rekit 把系统目录扫一遍，熟悉输出

第 2 周
  □ 解 2 个 crackme，写成分析文章（脱敏）
  □ 建博客/GitHub，把文章发出去

第 3 周
  □ 找一个自己买的正版软件，做一次完整的本地格式还原
  □ 写成第 3 篇文章，附可运行脚本

第 4 周
  □ 进 2–3 个逆向相关群，潜水观察
  □ 在 Upwork 建号，看 20 个逆向项目的需求和报价
  □ 复盘：我现在的作品集，能不能让一个陌生人相信我能干活？
```

**第 4 周那个问题，就是全部。**
