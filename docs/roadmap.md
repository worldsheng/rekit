# 逆向能力路线图

目标：能独立接单。不是"学完所有东西"，是**每个阶段产出一个能给别人看的东西**。

判断标准只有一条：**能不能在没人指路的情况下，把陌生样本拆到能回答问题**。

---

## 阶段 0：环境（1–2 周）

不装全，先装能跑通一条链的。

| 工具 | 用途 | 备注 |
|---|---|---|
| Ghidra | 免费反编译，脚本化 | 首选起步，IDA Free 其次 |
| x64dbg | Windows 动态调试 | 插件装 ScyllaHide（反反调试） |
| Detect It Easy (DIE) | 查壳/编译器指纹 | 比 PEiD 新 |
| PE-bear / CFF Explorer | 改 PE 头、看节区 | 改入口点、加节区 |
| Process Hacker / System Informer | 进程/句柄/内存 | 比任务管理器深得多 |
| Frida | 动态 hook | Python 侧也用它做自动化 |
| Wireshark + mitmproxy | 抓协议 | 配合 Frida 绕 pinning |
| rekit（本地） | 首轮筛查 | 本文档同目录 |

**产出**：能用 rekit + DIE + Ghidra 对任意一个 PE 在 5 分钟内说出：架构、是否加壳、导入面、疑似功能。

---

## 阶段 1：静态分析（3–4 周）

**学**
- x86/x64 常用指令集（不用背全，能读就行）
- 调用约定：stdcall / cdecl / fastcall / x64 的 rcx,rdx,r8,r9
- 栈帧、局部变量、参数传递
- 常见的编译器生成模式：`switch` 的跳转表、虚函数表、异常处理、字符串初始化
- 识别库函数：`strlen`、`memcpy`、`atoi` 的特征

**练**
- [crackmes.one](https://crackmes.one/) —— 按难度筛，先做 1–2 星的
- Ghidra 打开，先找 `main`，再看交叉引用

**产出**：写 3 篇 crackme 分析，每篇包含：入口点定位方法、关键比较逻辑的反编译代码、如何得出正确输入。

> 这三篇就是你的第一批作品集。**不要写"我用了什么工具"，要写"我怎么想到去看那里的"。**

---

## 阶段 2：动态调试（3–4 周）

**学**
- 断点类型：软件断点（0xCC）、硬件断点（DR 寄存器）、内存断点
- 条件断点、日志断点
- 调用栈回溯，识别"这个参数从哪来"
- 反调试对抗：`IsDebuggerPresent`、PEB.BeingDebugged、`NtQueryInformationProcess`、时序检测、硬件断点检测
- ScyllaHide 的各个选项对应在绕什么

**练**
- 拿阶段 1 的 crackme，**换用纯动态方式**再解一遍，不许看反编译
- 找一份加反调试的样本（crackmes 里标 "anti-debug" 的）

**产出**：一份"反调试绕过清单"，逐条写：检测手法 → 触发点 → 绕过方式（patch 地址 / hook / 改寄存器）。

---

## 阶段 3：脱壳（4–6 周）

**学**
- 壳的分类：压缩壳（UPX）、加密壳（ASPack）、虚拟化壳（VMProtect/Themida）、保护壳（Enigma）
- 脱壳通用流程：找 OEP → dump 内存 → 修复 IAT → 修节区
- OEP 定位：ESP 定律、`pushad/popad`、内存断点、单步跟进
- IAT 修复：Scylla、ImportREC
- 虚拟化壳：识别 VM 入口、handler 表、字节码提取

**练**
- UPX：`upx -d` 一行解决，但**手脱一遍**，理解原理
- ASPack / PECompact：手脱
- VMProtect：先只做到"能识别并说明为什么难"，不要求完整 devirtualize

**产出**：一个脱壳笔记仓库，每个壳一份：特征识别 → 步骤 → dump 出来的文件能正常运行。

---

## 阶段 4：算法 / 协议还原（4–6 周）

这是**最值钱**的一段，也是接单需求最集中的地方。

**学**
- 常见加密的识别：AES 的 S 盒常量、TEA/XTEA 的 delta 0x9E3779B9、RC4 的 256 字节 KSA、Base64 的字符表
- 定位密钥：静态搜常量、动态在 `CryptEncrypt`/`EVP_EncryptUpdate` 下断
- 协议结构：TLV、长度前缀、魔数、序列化格式（protobuf 的字段编号特征）
- 抓包还原：TLS pinning 绕过（Frida hook `SSL_verify` / OkHttp `CertificatePinner`）

**练**
- 找一个有本地加密存储的软件（很多笔记类/密码类 App），还原它的存储格式
- 找一个带签名的 App 接口，用 Frida 抓出签名前后的参数，离线复现签名

**产出**：一个"能跑的复现脚本"。不是伪代码——是输入原始数据，输出明文/合法请求的脚本。这是接单时给客户看的东西。

---

## 阶段 5：作品集（持续）

接单的人只看两样：**你能不能做**、**你做过没有**。

作品集结构（放博客/GitHub，链接放简历第一行）：

```
1. 脱壳笔记          ×3–5 个壳
2. crackme 分析      ×3–5 篇（含纯动态解法）
3. 协议还原          ×1–2 个完整复现（脱敏）
4. 工具              ×1 个自己写的（rekit 可以算，但最好再有一个解决具体问题的）
5. 反调试绕过清单    ×1 份
```

**不要写**：只贴工具截图、没有推理过程的"教程"、抄来的 PoC。

---

## 时间现实

每周投入 10–15 小时的情况下：

| 阶段 | 累计 |
|---|---|
| 0 | 2 周 |
| 1 | 6 周 |
| 2 | 10 周 |
| 3 | 16 周 |
| 4 | 22 周 |
| 作品集成型 | **6 个月左右** |

这是"能接第一单"的线，不是"成为高手"的线。高手是之后的事。

**如果 6 个月后还接不到单**，问题通常不在技术，在客户来源——看 `playbook.md`。

## 样本来源（合法）

| 来源 | 内容 |
|---|---|
| crackmes.one | 逆向练习题，按难度/平台/保护方式筛 |
| Flare-On（Mandiant 年度挑战） | 高质量的实战逆向题，有官方 writeup |
| pwn.college | 系统底层，偏漏洞利用 |
| HackTheBox / TryHackMe 的 reversing 分类 | 有环境 |
| 自己的软件 | 最合法：拿自己买的正版软件练手 |
| 恶意样本 | 只在隔离虚拟机里，且只在有明确分析目的时 |

**恶意样本永远不要在主系统上跑。** 虚拟机 + 快照 + 断网，这是操作前提不是建议。
